# 02. 48 小時運行結果

本文件記錄 `edu_crawler` 單次連續無人值守運行的實測行為，觀測視窗自
2026-09-17 00:49:32 起算，長度為整整 48 小時（172,800 秒）。內容涵蓋視窗內
的抓取統計、狀態碼與延遲分布、失敗原因分類、吞吐量隨時間的衰減與成因分析，
以及防爬蟲陷阱上限的實際效果。文中視窗彙總取自 `results/summary-48h.json`，
每小時吞吐量取自 `results/throughput-hourly.csv`；狀態碼、延遲百分位與失敗
原因分類由 `output/results_clean.jsonl` 重新計算，佇列、並發與丟棄連結等時序
指標取自 `output/metrics_log_clean.csv`，佇列與網域的結束狀態取自運行結束時
的 checkpoint，其摘錄保存於 `results/endstate-60h.json`。

## 2.1 運行設定

```bash
# 48 小時無人值守運行的完整啟動指令
python -m crawler.main \
  --seeds seeds.txt \
  --follow-links \
  --concurrency 50 \
  --queue-maxsize 50000 \
  --max-pages-per-domain 20 \
  --max-runtime-hours 48 \
  --checkpoint-interval 300
```

種子清單 `seeds.txt` 含 1,000 個網址。統計視窗為 2026-09-17 00:49:32 至
2026-09-19 00:49:32，整整 172,800 秒。該次 process 實際持續了 60.2 小時，
因此凡是落在視窗之外的數值，本文件一律明確標示，不與視窗內的數字混用。

| 失敗 | 64,439（5.10%） |
| `robots.txt` 略過 | 23,179 |
| 需要重試的請求 | 18,615（1.47%） |

「成功」一列採 `ok` 判定，其中 1,199,494 筆為 2xx、182 筆為 3xx。「不重複

### 2.2.1 狀態碼分布

以 1,264,115 次抓取為分母：200 佔 94.81%、404 佔 1.83%、403 佔 1.57%、
連線失敗（無狀態碼）佔 1.10%、429 佔 0.25%，其餘 4xx 與 5xx 合計 4,515 次、
佔 0.36%。

### 2.2.2 延遲百分位

以成功抓取為母體（n = 1,199,676）：p50 = 868 ms、p90 = 2,495 ms、
p99 = 6,019 ms、最大 14,381 ms。連線失敗的 13,860 次與被 `robots.txt`
擋下的 23,179 筆 `elapsed_ms` 均為 0，不列入此母體。

「其餘長尾」包含 content-encoding 解碼失敗、`Content-Length` 與

## 2.3 吞吐量衰減

吞吐量在 48 小時視窗內衰減約 9.2 倍，若一路量測到 60.2 小時 process 結束
則約 19 倍；在視窗結束之前，吞吐量早已遠離高峰。整段期間 worker pool 沒有
停止前進，衰減是連續而平滑的，並未出現任何一次卡死。

### 2.3.1 實測衰減

| 時點 | 每小時抓取次數 |
|---|---|
| 第 5 小時（高峰） | 67,614 |
| 第 12 小時 | 50,095 |
| 第 24 小時 | 19,968 |
| 第 36 小時 | 8,066 |
| 第 48 小時（視窗結束） | 7,354 |
| 第 60 小時（視窗之外，process 持續至 60.2 小時） | 3,553 |

第 1 至 48 小時加總為 1,264,115 次，與 §2.2 的抓取次數完全一致。

換算成速率：高峰的 18.8 次/秒 降到視窗結束時的 2.0 次/秒，即 **48 小時
視窗內衰減 9.2 倍**；若延伸到 process 結束時的 1.0 次/秒，則為 **19 倍**。
19 倍只有在視窗之外的第 59 至 60 小時才成立，不能與「48 小時」並列引用。

因此 §2.2 的 7.32 次/秒 是一個「健康階段與瀕死階段的混合平均」：視窗結束
時的實際速率只有約 2 次/秒，引用單一平均值會明顯高估系統的穩態能力。

### 2.3.2 成因：有效並發，而非網路延遲

p50 延遲從頭到尾穩定在約 870 ms，網路端並未變慢。真正衰減的是有效並發：
`crawler_inflight_requests` 的小時均值由第 6 小時的高峰約 26 降到視窗結束
時的約 3（上限為 `--concurrency 50`，見
[01-system-design.md](./01-system-design.md) §1.3），到 process 結束時
為 1。同一期間 `crawler_queue_depth` 在運行開始約 14 分鐘後便觸及
`--queue-maxsize 50000` 的上限，視窗內 90.4% 的取樣維持在 49,999 以上
（§1.4）；48 小時內因佇列已滿而被丟棄的連結累計 65,355,760 條
（`crawler_links_dropped_queue_full_total`，見 §1.4.1 與 §1.9）。

以 Little's law 檢驗，吞吐量 ≈ inflight ÷ 延遲 在各時點都成立，因此問題
可以精確地收斂成一句話：**為什麼 worker 花在 `fetch()` 之外的時間愈來愈
長**。視窗結束時 50 個 worker 合計只有 2.0 次/秒，平均每個 worker 約 24 秒
才完成一次循環，其中僅約 0.87 秒花在 `fetch()` 之內；到 process 結束時，
每次循環約需 50 秒。

### 2.3.3 已由實測排除的假設

兩個可能成因已由實測排除：

  - **佇列被少數網域佔據**（head-of-line blocking）：排除。process 結束
    （60.2 小時）時，佇列中 49,998 個待爬網址分散在 28,242 個網域，佔比
    最高的網域也只有 0.03%，分布過於分散，per-domain 限速不可能是瓶頸。
    這兩個數字是 60.2 小時的結束狀態，原始來源為運行結束時的 checkpoint，
    摘錄保存於 `results/endstate-60h.json`。
  - **checkpoint 阻塞 event loop**：部分成立，但不是主因。
    `write_checkpoint()` 確實是同步呼叫，會把 1,439,284 筆 `_seen`
    序列化成 86 MB 的 JSON，且隨著資料增長而變慢；但視窗內可量測的停頓
    共 67 段、加總 841 秒，單次最長 41 秒，僅佔視窗時間約 0.5%，遠不足以
    解釋 9 倍以上的衰減。

### 2.3.4 主要未證實假設：記憶體中無上限累積的狀態

目前尚未證實的主要假設是**記憶體中無上限累積的狀態造成 GC 停頓**：
process 結束時持有約 1,439,284 筆 `_seen` 網址、同量級的 referrer 紀錄、
181,888 個 `RobotFileParser` 物件，以及 `crawler/ratelimiter.py` 中三個各
181,888 筆、從不淘汰的 dict（semaphore、lock、last-start）。這個輪廓與
觀察到的現象一致——平滑單調的衰減、I/O 延遲持平、且沒有大型空窗（GC 停頓
多為次秒級，不會表現為 >20 秒的停止）。已對 `crawler/ratelimiter.py`
逐一確認：這三個 dict 沒有任何淘汰路徑。證實此假設需要另行以記憶體剖析
進行。

## 2.4 防爬蟲陷阱上限的實際效果

`--max-pages-per-domain` 上限（見
[01-system-design.md](./01-system-design.md) §1.5）確實在作用：process
結束時記錄的 181,888 個網域中，有 43,256 個（23.8%）已達到 20 頁的上限，
且 `domain_page_counts` 的最大值恰為 20，代表上限被硬性執行、沒有任何
網域越界。該網域總數是 60.2 小時的結束狀態，與 §2.3.3 同樣取自運行結束時的
checkpoint，摘錄保存於 `results/endstate-60h.json`；48 小時視窗結束時，
`crawler_distinct_domains_total` 為 174,973。

## 2.5 資料限制

  - **`bytes_received` 未列入統計** — 在未開啟 `--save-body` 的情況下，
    個別紀錄不帶回應大小，該值只以 process 生命週期內的累計計數器形式
    存在，無法歸屬到 48 小時視窗，因此 `results/summary-48h.json` 中該
    欄位為 `null` 而非 0。
  - **「觸及網域」與「實際發出請求的網域」不是同一件事** — 兩者相差
    6,845 個，那是只被 `robots.txt` 擋下、從未真正發出請求的網域。這正是
    `robots_blocked` 欄位（見
    [01-system-design.md](./01-system-design.md) §1.7）所要保留的證據；
    兩個數字分開列出，以免把「觸及」誤讀為「抓取」。
